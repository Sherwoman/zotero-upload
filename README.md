# Upload · Zotero 文献导入核对插件

一个面向 Zotero 的本地插件：**导入 PDF 前先核对元信息**，重复文献只增加分类，**从不覆盖已有的题录、附件、笔记和批注**。

> 当前版本 **1.1.2**，面向 Zotero **10.0.6**。

## 它解决什么问题

把新 PDF 拖进 Zotero 时，最容易出事的不是"导入失败"，而是**重复文献悄悄把已有题录和附件弄乱**：同一篇论文多出一条题录、原条目的 PDF 被替换、已经写好的笔记和批注对不上。

Upload 的做法是反过来：**先预览，再决定，最后才写入**。所有决定都由你逐条确认，插件不自动合并、不自动覆盖。

## 功能

| 操作 | 实际行为 |
| --- | --- |
| 仅给原条目增加分类 | 将目标分类加入原条目。保留原有分类，不新增题录或 PDF，不修改原字段、作者、附件、笔记和批注。 |
| 单独新增，保留此版本 | 新建独立题录并复制新 PDF。原条目不变。 |
| 保留为独立 PDF | 元信息尚不可靠时，只导入 PDF，留待人工检索，不编造题录。 |
| 跳过 | 文件预览不执行导入；普通导入待核对项继续保留。 |

窗口中的"预览"是只读的，不会在 Zotero 中创建临时文献。默认选项只是建议，**必须点击确认后才执行**，不自动写入文库。

## 安装

1. 下载仓库根目录的 [`Upload-1.1.2.xpi`](Upload-1.1.2.xpi)。
2. 打开 Zotero → **工具 → 插件**（Add-ons Manager）。
3. 右上角齿轮 → **Install Add-on From File…**，选择下载的 `.xpi`。
4. 重启 Zotero。

## 使用

1. 先在 Zotero 左侧选中目标文库分类，再点击工具栏的 **Upload**（或 工具 → **Upload · 文献导入…**）。
2. 点击"选择 PDF 并预览"，可以同时选择多个文件，也可在窗口内更换目标分类。
3. 核对每一项的默认处理方式，需要时展开匹配依据与文件路径，再点击"确认处理"。

文件预览完成后目标分类会锁定。需要更换时，点击"重新选择分类"，再重新预览，避免显示的分类与提交计划不一致。

### 普通导入也会被接管

用普通拖入 PDF、Zotero 的"检索元数据"等方式已经创建的 **新题录**，一旦出现相似候选，也会弹出核对窗口。选择复用时，插件先把新条目的分类加给原条目，再把刚导入的重复条目移入 Zotero 回收站（可恢复）；新 PDF 不会加给或替换原 PDF。

已有条目不会被当作待删除的新条目。若新条目已有笔记、标签、关联或批注，插件会拒绝收起它并保留双方。

> 普通导入监测只覆盖插件运行期间新建、且已有 PDF 的题录，不回溯整理整个旧文库。

## 匹配规则与边界

- **DOI 不同**：禁止复用，即使题名相同，也作为可能不同的发表版本处理。
- **DOI 一致**：核对题名，并检查已提供的作者、年份、发表类型和出处是否冲突。
- **缺 DOI**：优先核对本地附件的 SHA-256；否则要求完整题名、作者、发表年份和出处等充分佐证。证据不足只能跳过或独立保留。
- 题名比较会识别 `[2014 EOS/ESD]` 一类作者自加前缀，但**绝不改写原题名**。
- 每次提交都会重新检查文件和目标条目；文件发生变化、目标已删除或出现信息冲突时拒绝操作。

相似度不等于"同一版本"。没有可靠证据的候选不开放复用选项；程序不提供覆盖、替换附件、更新已有题录、通用条目合并或永久删除接口。

## 本机接口与命令行

插件在 Zotero 自带 HTTP 服务上注册只监听本机的前缀 `http://127.0.0.1:<port>/upload/v1`，只有 `health`、`context`、`preview`、`commit` 四个固定接口。除健康检查外均要求随机令牌，令牌写在 Zotero 配置目录的 `upload-local.json`，由命令行客户端自动读取。

`commit` 只接受预览计划号与逐项决定，不接受字段修改、附件替换或任意代码；网页跨域请求被拒绝。

```powershell
python -X utf8 .\upload_cli.py health
python -X utf8 .\upload_cli.py preview "C:\文献目录" --library 1 --collection ABCD1234 --out preview.json
```

第二条命令只生成预览文件。提交需要另外明确编写决定文件：

```json
{
  "planId": "从预览复制",
  "decisions": [
    {"rowId": "从预览复制", "action": "reuse", "targetKey": "原条目8位key"},
    {"rowId": "另一个rowId", "action": "new"},
    {"rowId": "再一个rowId", "action": "skip"}
  ]
}
```

```powershell
python -X utf8 .\upload_cli.py commit decisions.json
```

PDF 内容与题名比对在本机完成，**不上传 PDF**。外部请求只向 Crossref 公开接口提交两类信息：一是 PDF 中公开的 DOI；二是当 PDF 完全不含 DOI 时，提交**题名**做一次文献检索。题名检索结果只有在题名高度一致、且作者姓氏或发表年份能在 PDF 首页文本中得到佐证时才被采用，并在"匹配详情"里标注来源；否则一律保留待核对。无可靠结果或服务不可用时，仍采用本地证据。

## 兼容性

兼容范围**锁定为当前实际测试的 Zotero 10.0.6**，遵循"先验证再启用"。Zotero 升级后插件可能停用，需要重新验证后更新兼容范围。

插件不包含外部自动更新源，也不关闭 Zotero 的全局安全或兼容检查。

## 源码结构

| 文件 | 作用 |
| --- | --- |
| `core.js` | 匹配、严格请求校验、只加分类的最小写入函数（纯函数，无 Zotero 写入）。 |
| `upload.js` | 原生 Zotero 接口、PDF 解析、导入、普通导入监听。 |
| `content/` | 核对窗口（XHTML / CSS / JS / 图标）。 |
| `bootstrap.js` | 启动与关闭。 |
| `upload_cli.py` | 带鉴权的本机命令行客户端，仅用标准库。 |
| `addon_cli.py` | 通过临时 Marionette 会话调用 Zotero 原生插件管理器（仅调试用）。 |
| `build.py` | 按 `manifest.json` 版本号生成 `Upload-<version>.xpi`。 |
| `test_core.cjs` | 核心保护与默认规则测试（`node test_core.cjs`，无第三方依赖）。 |

## 自行构建

不需要任何第三方依赖，只要有 Python 3：

```powershell
python -X utf8 .\build.py
```

输出 `Upload-1.1.2.xpi`。构建是可复现的，产物 SHA-256 与上面记录的一致。

## 验证记录

本仓库只包含插件功能代码与构建脚本，不含任何个人文库、账号或使用记录。可自行运行 `node test_core.cjs` 复核核心保护与默认规则，并用 `python -X utf8 build.py` 复现安装包。

## 卸载

在 Zotero 插件管理器中移除 Upload 即可。卸载**不会**删除任何论文和附件，已增加的分类正常保留；本机令牌配置文件也不会自动删除，以免误删用户资料。
