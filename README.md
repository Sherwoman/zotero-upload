# Upload · Zotero 文献导入核对插件

一个面向 Zotero 的本地插件：**导入 PDF 前先核对元信息**，重复文献只增加分类，**从不覆盖已有的题录、附件、笔记和批注**。

> 当前版本 **1.1.5**，面向 Zotero **10.0.6**。

## 它解决什么问题

把新 PDF 拖进 Zotero 时，最容易出事的不是"导入失败"，而是**重复文献悄悄把已有题录和附件弄乱**：同一篇论文多出一条题录、原条目的 PDF 被替换、已经写好的笔记和批注对不上。

Upload 的做法是反过来：**先预览，再决定，最后才写入**。所有决定都由你逐条确认，插件不自动合并、不自动覆盖。

## 功能

| 操作 | 实际行为 |
| --- | --- |
| 仅给原条目增加分类 | 将目标分类加入原条目。保留原有分类，不新增题录或 PDF，不修改原字段、作者、附件、笔记和批注。 |
| 单独新增，保留此版本 | 新建独立题录并复制新 PDF。原条目不变。 |
| 保留为独立 PDF | 元信息尚不可靠时，只导入 PDF，留待人工检索，不编造题录。 |
| 跳过 | 文件预览不执行导入；普通导入待核对项继续保留。 |

窗口中的"预览"是只读的，不会在 Zotero 中创建临时文献。默认选项只是建议，**必须点击确认后才执行**，不自动写入文库。

## 安装

1. 下载仓库根目录的 [`Upload-1.1.5.xpi`](Upload-1.1.5.xpi)。
2. 打开 Zotero → **工具 → 插件**（Add-ons Manager）。
3. 右上角齿轮 → **Install Add-on From File…**，选择下载的 `.xpi`。
4. 重启 Zotero。

## 使用

1. 先在 Zotero 左侧选中目标文库分类，再点击工具栏的 **Upload**（或 工具 → **Upload · 文献导入…**）。
2. 点击"选择 PDF 并预览"，可以同时选择多个文件，也可在窗口内更换目标分类。
3. 核对每一项的默认处理方式，需要时展开匹配依据与文件路径，再点击"确认处理"。
4. 需要回退**已经导入过**的重复文献时（例如导入时窗口出错过，或重启 Zotero 后它不再出现在待核对列表里）：在 Zotero 中选中该条目，再点击窗口右下角的 **核对选中的库内条目**，就能重新拿到同样的"仅增加分类"回退选项；选中的条目没有可复用重复项时会给出提示，且不会清空当前预览。

文件预览完成后目标分类会锁定。需要更换时，点击"重新选择分类"，再重新预览，避免显示的分类与提交计划不一致。

### 普通导入也会被接管

用普通拖入 PDF、Zotero 的"检索元数据"等方式已经创建的 **新题录**，一旦出现相似候选，也会弹出核对窗口。选择复用时，插件先把新条目的分类加给原条目，再把刚导入的重复条目移入 Zotero 回收站（可恢复）；新 PDF 不会加给或替换原 PDF。

已有条目不会被当作待删除的新条目。若新条目已有笔记、标签、关联或批注，插件会拒绝收起它并保留双方。

> 普通导入监测只覆盖插件运行期间新建、且已有 PDF 的题录，不回溯整理整个旧文库。待核对列表只存在于内存，重启 Zotero 后不会自动重建；需要回退已经导入过的条目时，用"核对选中的库内条目"按当前选集重新核对。

## 匹配规则与边界

- **DOI 不同**：禁止复用，即使题名相同，也作为可能不同的发表版本处理。
- **DOI 一致**：核对题名，并检查已提供的作者、年份、发表类型和出处是否冲突。
- **缺 DOI**：优先核对本地附件的 SHA-256；否则要求完整题名、作者、发表年份和出处等充分佐证。证据不足只能跳过或独立保留。
- 题名比较会识别 `[2014 EOS/ESD]` 一类作者自加前缀，但**绝不改写原题名**。
- 每次提交都会重新检查文件和目标条目；文件发生变化、目标已删除或出现信息冲突时拒绝操作。

相似度不等于"同一版本"。没有可靠证据的候选不开放复用选项；程序不提供覆盖、替换附件、更新已有题录、通用条目合并或永久删除接口。

## 本机接口

插件在 Zotero 自带 HTTP 服务上注册只监听本机的前缀 `http://127.0.0.1:<port>/upload/v1`，只有 `health`、`context`、`preview`、`track`、`commit` 五个固定接口。除健康检查外均要求随机令牌，令牌写在 Zotero 配置目录的 `upload-local.json`。其中 `track` 只对当前选中的条目做一次重复核对并返回待核对计划，不写入文库；`commit` 只接受预览计划号与逐项决定，不接受字段修改、附件替换或任意代码；网页跨域请求被拒绝。

PDF 内容与题名比对在本机完成，**不上传 PDF**。外部请求只向 Crossref 公开接口提交两类信息：一是 PDF 中公开的 DOI；二是当 PDF 完全不含 DOI 时，提交**题名**做一次文献检索。题名检索结果只有在题名高度一致、且作者姓氏或发表年份能在 PDF 首页文本中得到佐证时才被采用，并在"匹配详情"里标注来源；否则一律保留待核对。无可靠结果或服务不可用时，仍采用本地证据。

## 兼容性

兼容范围**锁定为当前实际测试的 Zotero 10.0.6**，遵循"先验证再启用"。Zotero 升级后插件可能停用，需要重新验证后更新兼容范围。

插件不包含外部自动更新源，也不关闭 Zotero 的全局安全或兼容检查。

## 校验

本仓库只发布可直接安装的插件包 `Upload-1.1.5.xpi`，不含任何个人文库、账号或使用记录。安装前可用上面的 SHA-256 核对文件完整性。

## 卸载

在 Zotero 插件管理器中移除 Upload 即可。卸载**不会**删除任何论文和附件，已增加的分类正常保留；本机令牌配置文件也不会自动删除，以免误删用户资料。

## 更新记录

### 1.1.5（2026-10-18）

补上"重启之后还能回退"的入口：待核对列表只在内存里，重启 Zotero 就没了，因此因为窗口报错而没能核对、之后又重启过的重复文献，在 1.1.4 里只能靠重新选文件预览来救。1.1.5 把这条路做成了窗口里的一个按钮。

- 核对窗口右下角新增 **核对选中的库内条目**：对当前在 Zotero 中选中的条目逐个调用已有的重复核对流程（非普通条目、已删除、无附件、无题名、无可复用候选一律跳过，不复制判定逻辑），结果直接进入同一张待核对列表；
- 新增只读本机接口 `track` 承载这一操作，除健康检查外同样要求令牌，不写入文库；
- 选中条目没有可复用重复项时只给状态提示，**不会清空**当前已经加载的预览行；
- 顺带修掉 `setWorking()` 里的一处隐患：禁用控件时若控件没有 `dataset` 会抛 `Cannot set properties of undefined`，现在先判空再写；
- `test_ui_flow.cjs` 扩充到 30 项，1.1.5 全过；同一脚本对 1.1.2 源码 4 过 26 败，仍复现 `Cannot read properties of undefined (reading 'split')`。

### 1.1.4（2026-10-18）

把核对窗口的初始化链路整体改为不会中断，1.1.2 遗留的三个症状一起消失：窗口能打开并列出待处理条目（普通导入的新文献可以回退）、文件夹选择的 PDF 能进入预览、提交按钮可用。

- 取值统一走 `valueOf(action)`：`action.value` → `dataset.value` → `skip` 三级兜底，任何控件异常都不再抛 `split` 崩溃；
- `render()` 拆出逐行 `renderRow()`，单行元信息异常只跳过该行；
- `theme()`、分类下拉、待处理列表各自独立兜底，任一环节失败都不影响窗口其余部分；
- `choose()` 用 `try/catch/finally` 保证选择状态一定复位，空选择给出提示而不是卡住；
- 新增 `test_ui_flow.cjs`：假 DOM 端到端跑通 init → 待处理 → 选择 PDF → 改选 → 提交；同一脚本在 1.1.2 上复现 `split` 崩溃（14 项失败），在 1.1.4 上 18 项全过。

注意：待处理列表只存在于内存，重启 Zotero 不会重建。因崩溃没能核对、之后又重启过的条目，需要重新用文件夹选择预览一次，同样会给出"复用"回退选项（1.1.5 起也可以直接选中条目点"核对选中的库内条目"）。

### 1.1.3（2026-10-18）

修复核对窗口一打开就报 `can't access property "split", c.action.value is undefined` 的问题。

1.1.2 把每行的"处理方式"从原生 `<select>` 换成分段按钮组，但构造函数返回的是外层容器元素，`value` 的取值器挂在了另一个内部对象上。于是 `render()` 建好行之后，`updateSummary()` 统计 `action.value` 得到 `undefined`，`split(":")` 抛错，核对窗口无法使用。

- 取值/禁用接口改为直接定义在返回的元素上，`render()`、`setWorking()`、`commit()` 仍按 `<select>` 的方式读写；
- 统计与提交对空值兜底为 `skip`，单个控件异常不再让整个窗口崩溃；
- 新增 `test_ui_controls.cjs`：在假 DOM 中加载 `content/review.js`，覆盖取值、切换、禁用与统计；同一测试在 1.1.2 上复现该 `split` 报错（7 项失败），在 1.1.3 上 10 项全过。
